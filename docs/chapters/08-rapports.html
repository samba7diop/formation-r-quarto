9  Rapports et communication des résultats

9.1 Introduction

Une analyse n’a de valeur que si elle est compréhensible et reproductible. Quarto (et R Markdown) permettent de mêler texte, code R et résultats dans un même document source, puis de générer HTML, PDF ou Word.

9.2 Objectifs pédagogiques

  • Comprendre la logique des documents reproductibles
  • Structurer un fichier .qmd
  • Paramétrer l’exécution des blocs de code
  • Générer HTML, PDF et DOCX
  • Gérer bibliographie et mise en page
  • Comparer Quarto et R Markdown

9.3 Prérequis

Avoir Quarto installé (Section 2.7). Notions de Chapter 7.

9.4 Documents reproductibles

Principe : une source → plusieurs formats. Modifier les données ou le code, puis recompiler, met à jour tables et figures automatiquement.

Vocabulaire
  • YAML : en-tête de métadonnées (--- … ---)
  • Chunk / bloc : segment de code exécutable
  • Rendu (render) : compilation vers HTML/PDF/DOCX
  • Freeze / cache : options pour accélérer les rebuilds

9.5 Présentation de Quarto

Quarto unifie R, Python, Julia et Markdown. Ce livre est lui-même un projet Quarto de type book (voir _quarto.yml).

9.6 Structure d’un fichier .qmd

---
title: "Mon rapport"
author: "Prénom Nom"
format: html
---

## Introduction

Texte en **Markdown**.

```{r}
summary(mtcars$mpg)

## Titres, listes, tableaux et liens

```markdown
## Titre niveau 2
- liste à puces
1. liste numérotée
[Lien interne](#sec-rapports)

Tableau Markdown :

Indicateur Valeur
n 32
moyenne 20.09

9.9 Paramètres d’exécution

Option Effet
echo: false cache le code, montre le résultat
eval: false montre le code sans l’exécuter
include: false exécute mais n’affiche rien
warning: false masque les warnings

Dans _quarto.yml, la section execute: fixe les défauts du livre.

9.10 Génération HTML, PDF, DOCX

Depuis le dossier formation-r/ :

quarto preview                 # HTML interactif
quarto render --to html
quarto render --to docx
quarto render --to pdf         # nécessite LaTeX / TinyTeX

9.10.1 Dépendances par format

Format Besoin principal
HTML Quarto + packages R utilisés
DOCX Quarto (pandoc inclus)
PDF Distribution LaTeX (TinyTeX recommandé) 
tinytex::is_tinytex()
# sinon : tinytex::install_tinytex()
Vérifier sans tout rebuild

quarto render chapters/08-rapports.qmd --to html pour tester un fichier isolé (selon configuration).

9.11 Personnalisation de la mise en page

  • HTML : theme, CSS (styles/styles.css), toc
  • PDF : geometry, documentclass, colorlinks
  • DOCX : reference-doc (modèle Word) si besoin

9.13 Rapports statistiques automatisés

library(tidyverse)
ventes <- read_csv("data/ventes.csv", show_col_types = FALSE) |>
  filter(!is.na(region))

    n = n(),

resume

En produisant le document chaque semaine sur des données mises à jour, le texte descriptif et les chiffres restent synchronisés.

9.14 R Markdown vs Quarto

Aspect R Markdown Quarto
Extension .Rmd .qmd (aussi .Rmd)
Moteur rmarkdown / pandoc Quarto CLI
Livres / sites bookdown intégré (type: book)
Multi-langage possible natif
Avenir Posit maintenu recommandé pour nouveaux projets

Les compétences Markdown + chunks se transfèrent presque à l’identique.

9.15 Publication et partage

  2. GitHub Pages : publier le dossier HTML généré
  3. Posit Connect / serveur interne : déploiement organisationnel
  4. Envoyer le DOCX ou PDF par e-mail

Exemple GitHub Pages (facultatif) :

git commit -m "Livre formation R"
# Configurer GitHub Actions ou pousser le site rendu

Ne publiez jamais de données personnelles non anonymisées.

# Rapports et communication des résultats {#sec-rapports}

## Introduction

Une analyse n'a de valeur que si elle est **compréhensible** et **reproductible**. Quarto (et R Markdown) permettent de mêler texte, code R et résultats dans un même document source, puis de générer HTML, PDF ou Word.

## Objectifs pédagogiques

- Comprendre la logique des documents reproductibles
- Structurer un fichier `.qmd`
- Paramétrer l'exécution des blocs de code
- Générer HTML, PDF et DOCX
- Gérer bibliographie et mise en page
- Comparer Quarto et R Markdown

## Prérequis

Avoir Quarto installé (@sec-installation). Notions de @sec-visualisation.

## Documents reproductibles

Principe : **une source → plusieurs formats**. Modifier les données ou le code, puis recompiler, met à jour tables et figures automatiquement.

::: {.callout-note}
## Vocabulaire
- **YAML** : en-tête de métadonnées (`---` … `---`)
- **Chunk / bloc** : segment de code exécutable
- **Rendu (*render*)** : compilation vers HTML/PDF/DOCX
- **Freeze / cache** : options pour accélérer les rebuilds
:::

## Présentation de Quarto

Quarto unifie R, Python, Julia et Markdown. Ce livre est lui-même un projet Quarto de type `book` (voir `_quarto.yml`).

## Structure d'un fichier `.qmd`

```markdown
---
title: "Mon rapport"
author: "Prénom Nom"
format: html
---

## Introduction

Texte en **Markdown**.

```{r}
summary(mtcars$mpg)
```
```

## Titres, listes, tableaux et liens

```markdown
## Titre niveau 2
- liste à puces
1. liste numérotée
[Lien interne](#sec-rapports)
```

Tableau Markdown :

| Indicateur | Valeur |
|------------|--------|
| n | 32 |
| moyenne | 20.09 |

## Insertion de code R

```{r chunk-demo}
mean(mtcars$mpg)
```

Options utiles dans l'en-tête du bloc : `echo`, `eval`, `warning`, `message`, `fig.width`, `fig.height`, `label`.

## Affichage des résultats et graphiques

```{r rapport-plot, fig.cap="Consommation selon le poids (exemple de rapport)"}

|--------|-------|
